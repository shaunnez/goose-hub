# Mission

Goose Hub is a personal command centre for AI-assisted software delivery, powered by Factory: an orchestration engine that turns work items into structured agent runs through observable, gated workflows.

It exists for one user (Shaun) and one purpose: making a senior engineer materially more effective by orchestrating AI agents across many projects with control, observability, and trust.

## What it is

- A local-first app that aggregates work from many target repositories
- An orchestrator that runs role-scoped AI agents through versioned skill chains
- A workspace where ideas are captured, refined, decomposed, built, validated, retrospected, and shipped
- A system that improves itself by running on itself

## What it is not

- A multi-tenant SaaS product
- A hosted service
- A replacement for human judgement
- A general-purpose autonomous coder
- A competitor to Anthropic, GitHub, Linear, or any other tool in the harness category

## What it stands for

1. The orchestrator decides; agents recommend; humans approve gates.
2. Work-item state lives in the project's own source of truth, never centralised in Goose Hub.
3. Vertical slices over horizontal layers, every time.
4. Boring transparent heuristics over fancy ML when trust matters.
5. Holdouts are sacred. Validators never see implementation reasoning.
6. Supervised by default; autonomous by explicit configuration.
7. The system is built using itself: every feature is a GitHub issue picked up by Factory.

## Whose system this is

This is one engineer's tool. It is opinionated. It is built to be used by Shaun first, with clean interfaces so it could be adapted later if circumstances demand. Generality is a side effect of clean design, never the goal.

## How to read this

This file is immutable. Factory cannot modify it. Humans can modify it through direct repo access, but should not — Mission is set at M0 and held.

If the mission feels wrong later, that is a signal to start a new project, not to mutate this one.
