# M6 Retrospective — Investigation Workflow

**Closed:** 2026-05-02
**Issues shipped:** 8 (M6.01–M6.08), plus three smoke-test/demo issues (#173, #211, #214) and one real bug demo (#215)
**PRs merged:** 5 (#193, #194, #195, #197, #198) — followed by 8 unsquashed `fix:` commits on main

## What worked

The combined PRs were the right calls. M6.03 + M6.04 (`skills/investigate/` + `skills/playwright-repro/`) shipped together because the investigator dispatches the playwright-repro skill internally for `type:bug`. M6.06 + M6.07 (Investigation tab UI + Code tab UI) shipped together because both tabs read from the same `agent.investigation-complete` event payload. Splitting either pair into separate PRs would have meant landing one half with no consumer.

Issue #215 was the real demo. A genuine bug (the prev/next nav buttons in the detail view have no disabled state and silently fail at boundaries) was filed mid-milestone, picked up by the M5 webhook → triage chain, classified as `type:bug priority:medium`, then handed to the M6 investigator which produced structured findings citing the key file and the offending lines (`apps/web/src/components/detail/components/DetailPage.tsx:166–177`). The whole point of M5+M6 — issues file → automatic classification → automatic investigation — was demonstrated against a real defect, not a fixture.

Worktree creation/cleanup as M6.01 was the right structural choice. Building the sandbox boundary first meant M6.02's `read` and `search` tools had a settled root to enforce against. The tools take a `workspaceRoot` and reject absolute paths or `../` traversal with a typed `SandboxViolationError` — a clean boundary that downstream M7 dev tools (`write`, `bash`) can extend without re-litigating.

`select-persona.ts` (round-robin persona selection) shipped in M6.05's PR. M9's roster needs this; building it now while the architectural alignment is fresh is correct, even though the consumer is two milestones away. M6's README notes the deferred consumer — better than M1, where deferred consumers shipped silently.

The investigator's decision-summary filtering was added to `core/agent-runtime/context-assembly.ts` in M6.05. This is a free down-payment on M8's holdout enforcement: when QA and Review run, the investigator's summaries are already filtered out of their context. The architecture matters — M8 is mostly enforcement and tests, not new infrastructure.

## What didn't work

**Eight `fix:` commits landed on main between the M6.06+07 merge and milestone close, all unsquashed.** Listed in commit order:

1. `5e44607 fix: webhook handler dispatches factory:investigating label to investigate workflow` — the headline flow (issue triaged to `factory:investigating` → investigate workflow runs) was broken on first ship. The webhook → workflow dispatch was the M6 promise and it didn't work until this fix.
2. `6ff92fe fix: use runtime URL resolution for cross-package slice import` — TypeScript path alias broken at runtime.
3. `cae41f0 fix: read skill.md not prompt.md in investigate workflow` — file naming mismatch. `skills/investigate/` had `prompt.md` but the workflow loaded `skill.md`.
4. `e3ea0a7 fix: investigate workflow timeout and state transition on failure` — failure path didn't transition state, leaving issues stuck in `factory:investigating`.
5. `6b0285d fix: dependency parser colon-optional + triage-batch 10-item cap` — also adds a triage-batch cap; M5 leaked into the M6 close.
6. `f26b993 fix: build errors and e2e regression from M6.06/M6.07 UI changes` — the UI PR broke the build.
7. `ec00690 fix: Windows test failures — path separators, sandbox check, rg missing` — `core/tool-layer/tools/read.ts` used hardcoded `'/'` for the sandbox check; broken on Windows.
8. `02348f7 fix: Biome lint/format corrections in M6 UI files` — and the lint regression returns for the third milestone in a row.

Five of the eight (1, 2, 3, 4, 6) are integration-level bugs the slice tests didn't catch. M6.05's PR (#197) added 506 lines of slice tests and shipped with the webhook handler not actually dispatching to the workflow — the slice test exercised the workflow function directly, never the route that calls it.

**Cross-platform code wasn't tested cross-platform until after merge.** `core/tool-layer/tools/read.ts` used `'/'` as a hardcoded path separator for the sandbox-violation check. The slice test passed on Linux/Mac. Windows broke. Path math is exactly the kind of thing where a single missed `path.sep`/`path.join` call is silent until the OS changes.

**M6.08 acceptance closed without a committed e2e test.** The issue acceptance criteria included "Test lives in `slices/investigate/` or a dedicated e2e suite." The actual demonstration of the headline criterion was issue #215 — by hand, against the live UI. There's a manual smoke run, but no scripted equivalent of `scripts/smoke-test-m5.ts` for M6's pipeline. The criterion was checked off but the artefact isn't in the repo.

**No ADRs for the new core/ surfaces.** Two architectural decisions shipped in M6 with no `docs/adr/` entry:
- `core/workspaces/worktree.ts` — git worktree as the unit of agent isolation. Every M7+ dev tool inherits this assumption.
- `core/tool-layer/tools/read.ts` + `search.ts` sandbox model — `workspaceRoot` containment, absolute-path rejection, traversal rejection, ripgrep delegation for search. This is the contract every future read-style tool must satisfy.

ADR 0014 (M8 holdout enforcement) was filed for M8 prep before M6 retros existed; the M6 ADRs that should've been written are still missing. Same recurring miss as M1, M2, M4, M5.

**No PRs milestoned.** Sixth milestone in a row. `gh pr list --milestone "M6: Investigation Workflow"` returns zero. M5 retro asked for this to be hooked or scripted; it wasn't done.

## What to change for M7

1. **Integration test for any workflow dispatched via webhook.** If a workflow is reachable through `POST /webhooks/github`, there must be a test that calls the route handler with a representative payload and asserts the workflow runs. The five wiring bugs in M6 (webhook dispatch, file-name resolution, runtime URL, timeout transition, build regression) would have been caught in seconds by one such test. The slice test alone is not sufficient.

2. **Path math goes through `path.sep`/`path.join`.** Add a Biome lint rule (or a grep check in CI) for hardcoded `'/'` separators in `core/` path operations. The Windows fix in `read.ts` is the second time this class of bug has shipped (M3 had a similar one in CLI argv handling).

3. **ADRs for `core/workspaces/` and `core/tool-layer/tools/`.** Write them now while the decisions are fresh, not in the next exit audit. The sandbox model is the foundation M7's `write`/`bash`/`test` tools build on — getting the contract on paper before M7 tools extend it is cheap insurance.

4. **Squash post-merge fixes into the originating PR, or open a follow-up issue per fix.** Eight unsquashed `fix:` commits between M6.06+07 and milestone close make the M6 history hard to read and impossible to revert cleanly. Either rebase fixes into the PR before merge, or file them as `M6.bug.<N>` issues so they're tracked.

5. **PR milestoning, finally.** Sixth milestone of asking. If it's not happening manually, it's not going to start happening. Add a wrapper around `gh pr create` in this repo, or a post-create hook that sets the milestone based on the active milestone label.

6. **Generalise the smoke-test artefact for M6.** Move `docs/smoke-test-m5.md` to `docs/smoke-tests/m5.md` and add `m6.md` covering "file a `type:bug`, see investigation findings appear within budget, verify Playwright capture exists." Pair it with `scripts/smoke-test-m6.ts` if the scripted verifier pattern continues. M5 demonstrated the value; M6 lacks the equivalent.
