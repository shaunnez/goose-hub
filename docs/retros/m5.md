# M5 Retrospective — Real Triage and Repo Matching

**Closed:** 2026-05-02
**Issues shipped:** 8 (M5.01–M5.07 + smoke-test demo issue #173)
**PRs merged:** 7 (#161–#167)

## What worked

The seven M5 issue PRs landed within roughly an hour of each other. M5.01 and M5.02 were independent and shipped first; M5.03 (`triage-batch` workflow) consumed both, and M5.04–M5.07 chained off it cleanly. The decomposition in the issue list mirrored the dependency graph, so parallelism worked without collisions.

The three-tier repo matcher landed with the threshold-gating intact. Tier 2 only runs if tier 1 is not confident; tier 3 only runs if tier 2 produces no clear winner. This is the cost-discipline pattern PLAN.md specifies and it was respected — the easiest demo case (filing an issue obviously about goose-hub) stops at tier 1 and never spends a code-search call.

The `target-projects/goose-hub-self/repos.md` allowlist format is extensible for M14 multi-repo. One entry shipped (`shaunnez/goose-hub`), but the file structure (`### [slug](url)\n**Description:** …`) is reusable for the multi-project world without a schema migration.

The headline exit criterion was demonstrated end-to-end this milestone, which is what M4's retro asked for. Smoke-test issue #173 (`[smoke] M5 test issue 6`) was filed live in GitHub, picked up by the webhook within the configured budget, triaged to `type:chore` + `priority:low`, the repo candidate comment was posted, and the issue moved to `factory:accepted`. That's the full pipeline. The scripted verifier `scripts/smoke-test-m5.ts` plus the runbook in `docs/smoke-test-m5.md` mean the criterion is repeatable, not a one-off.

The `TriageResultsSection` UI hides itself when the triage event is absent — graceful absence rather than a placeholder. This is the right pattern for the surfaces M6+M7 will add (Investigation, Code, QA, Review tabs).

## What didn't work

**Lint broke on main again.** Commit `b14ac7f chore: fix lint — remove unused contextXml, fix template literal` landed after the seven M5 PRs merged, with no PR. M3 retro flagged this. M4 retro flagged this. M5 repeats it. The rule is now five milestones old and structurally unenforced — there is still no required CI gate before merge.

**No PRs were milestoned.** `gh pr list --milestone "M5: Real Triage and Repo Matching"` returns zero. M1, M2, M3, and M4 retros all flagged this; the issue–PR linkage gap is now five milestones long. The `gh pr create` command in slice work flows still doesn't include `--milestone`. A muscle-memory fix isn't sticking; this needs to be a hook or template.

**No ADRs filed in the M5 window.** ADRs 0009–0010 covered M4. The next ADR (0011 on Playwright test agents) was written as M5-prep but was actually committed during the M7-prep block (`acdb62b0 M5-prep: Playwright test-agents scaffold + ADR 0011 (#236)`) — well after M5 closed. Two M5 surfaces deserved ADRs at implementation time and didn't get them: the GitHub webhook security model (HMAC-SHA256 with `GITHUB_WEBHOOK_SECRET`, refuse-to-start if unset) and the `agent.repo-override` event as the canonical override mechanism (override beats agent candidate). Both are contracts other code now depends on.

**A 13-commit server-architecture refactor landed between M5 close and M6 start with no tracking issue.** PR #188 (`feature/server-api-architecture`) restructured `apps/server` into per-domain routers (events, projects, webhooks, workflows, issues, inbox, milestones), added `apps/server/STANDARDS.md`, and updated documentation chains. It's a real improvement and the architecture is cleaner — but it shipped as off-the-books work during a milestone gap. Either it should have been an M5 follow-up issue (with acceptance criteria) or a filed M6 prerequisite. Future milestones will struggle to audit "what shipped in M5" if substantial refactors keep landing in the seam.

**Smoke-test runbook is milestone-specific.** `docs/smoke-test-m5.md` and `scripts/smoke-test-m5.ts` are named for M5. M6 onwards needs the same exercise — file an issue, watch the pipeline, verify the headline criterion — but the file naming doesn't generalise.

## What to change for M6

1. **CI green before merge, structurally.** Five milestones of "remember to run lint" is enough. Either add a branch protection rule that requires the `Lint, typecheck, test` job to pass, or add a pre-push hook in this repo that runs `pnpm lint && pnpm typecheck && pnpm test` and refuses to push if any fail. Verbal discipline is not working.

2. **PR milestoning by hook, not by memory.** Add `--milestone` to a wrapper script around `gh pr create`, or open a tracking issue to script `gh pr edit <N> --milestone "<active>"` against every PR opened on a `claude/*` branch. The carry-over from M1–M4 is now a five-milestone-long process bug.

3. **ADRs at implementation time, not in the exit audit.** The webhook auth model (HMAC-SHA256, refuse-to-start) and the `agent.repo-override` precedence rule both need ADRs in `docs/adr/`. Write them as part of the M6 batch since they're recent enough to remember.

4. **Track unscoped work as filed issues.** The server domain refactor should have been a filed issue with acceptance criteria. Going forward, any refactor that touches `apps/` or `core/` and is more than a single commit gets its own issue, even if it lives in a milestone gap.

5. **Generalise the smoke-test pattern.** Move `docs/smoke-test-m5.md` to `docs/smoke-tests/m5.md` and write `m6.md` for the M6 headline flow at the same time as the M6.08 e2e test. The runbook is the human-checked complement to the scripted verifier; both need a per-milestone home.
