# M1 Retrospective — Bootstrap Source of Truth

**Closed:** 2026-04-30  
**Issues shipped:** 11  
**PRs merged:** 14 (including skeleton, lint fixes, worktree cleanup)

## What worked

TDD discipline held throughout. Every core module arrived with tests before the surface code that consumed it; the conflict resolver in particular had 16 cases covering all seven scenario types before the CLI ever called it. The 79-test suite and sub-second CI run are a strong foundation to build M2 on.

The vertical decomposition held. Each issue was narrow enough to merge cleanly, and no PR ballooned into adjacent work. The `core/state-source` → `core/state-machine` dependency direction was obvious and stayed consistent across all PRs.

The exit criterion (`goose status goose-hub-self` against real GitHub) was a good forcing function. It required the entire read path to work end-to-end, not just in unit tests.

## What didn't work

**ADRs were never started.** PLAN.md line 2146 requires an ADR for every PR that touches `core/`. Six PRs touched core/ in M1 and zero ADRs were written. The root cause: the issue decomposition came directly from PLAN.md section 28's deliverable list, which doesn't mention ADRs — they're a process rule buried elsewhere. No agent caught it mid-milestone, and no PR template enforced it.

**PRs were not linked to the GitHub milestone.** All 14 merged PRs show `milestone: null` in the GitHub API. The issues were correctly milestoned; the PRs were not. This broke `gh pr list --milestone` queries during the audit.

**`transitions.ts` and `core/db/` have no live consumers yet.** Both are correct implementations with passing tests, but the CLI doesn't call either (it's read-only and uses `GitHubLabelsSource` directly). The first real consumers land in M2. This is by design but wasn't explicitly tracked as a known gap.

## What to change for M2

1. **File an ADR before merging any PR that touches `core/`.** Add this to the issue template or acceptance criteria for every M2 issue that modifies `core/`. The `docs/adr/` directory now exists; use it.

2. **Set the milestone on PRs, not just issues.** Add `--milestone "M2: ..."` to `gh pr create` calls, or set it immediately after opening.

3. **Track deferred consumers explicitly.** When a `core/` module is built ahead of its consumer, note the expected consumer milestone in a comment or follow-up issue so it doesn't read as dead code.
