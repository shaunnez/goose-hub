# CLAUDE.md

You are an AI agent working on Goose Hub. Read this file first, every time, before any task.

## Role

Goose Hub is a personal command center for AI-assisted software delivery, powered by Factory, the orchestration engine inside it. One user, local-first, opinionated. See `MISSION.md` for the full product statement.

Execute one narrow task at a time. When a GitHub issue is provided, the issue is the build spec.

## Source of Truth

- `CONTEXT.md` is the resolved implementation-decision registry. Read it before writing code in `core/` or `apps/`. If it covers the decision you are touching, follow it.
- `docs/adr/` records the longer reasoning behind decisions. Use ADRs when you need the why, or when a new `core/` architectural decision is required.
- `FACTORY_RULES.md` is the canonical governance rule list. Do not mirror it here; read it for rule text.
- `docs/inventory.md` is generated by `pnpm manifest` and maps packages, slices, skills, apps, and target projects. Do not hand-maintain competing catalogues.
- `core/types.ts` is canonical for shared TypeScript unions such as `Role`.
- App READMEs are mandatory before app edits: `apps/server/README.md` for server work and `apps/web/README.md` for web work.

Run `pnpm audit-docs` before opening a PR that touches `core/types.ts`, the skill catalogue, or governance docs.

## Domain Terms

- **Goose Hub**: the product, app, UI, and runtime.
- **Factory**: the engine inside Goose Hub: orchestrator, workflows, agent runtime, tool layer, workspaces, budgets, telemetry.
- **Work Item**: a unit of work in the source of truth.
- **State**: the lifecycle position of a work item. Stored on the issue, not the PR.
- **Lane**: a Kanban display grouping. It never drives behavior.
- **Workflow**: a TypeScript module composing nodes that move a work item through states.
- **Agent Run**: one invocation of an AI agent with role, prompt, tool allowlist, budget, and output schema.
- **Role** — triager, griller, prd-writer, decomposer, researcher, investigator, developer, dev-reviewer, qa, reviewer, retrospector, auditor, intervention-proposer, assistant.
- **Governance**: immutable rules in `MISSION.md`, `FACTORY_RULES.md`, and `CLAUDE.md`.
- **Decision Summary**: a single-sentence, schema-constrained event emitted at a decision point. It is not raw chain-of-thought.

Look up less common vocabulary in `CONTEXT.md`, `FACTORY_RULES.md`, or the relevant code before guessing.

## Non-Negotiables

- Read before editing. Before modifying a function, inspect its callers. Research before you change code.
- Follow TDD for implementation: failing test, implementation, refactor.
- Keep work vertical. Slices include only the surfaces they touch; `slice.test.ts` and `README.md` are required.
- Slices import from `core/` through public interfaces only. Slices never import from other slices.
- Skills are versioned. Each skill has `prompt.md`, `schema.ts`, and `skill.config.ts`. Runtime prompts are loaded through `readPromptWithContext()`; inline prompts in code fail review.
- Every agent run produces JSON conforming to its skill schema. Free-text-only outputs fail.
- State labels live on issues, not PRs.
- QA and Review are holdouts. They never see implementation reasoning.
- Governance files cannot be modified by a Factory PR unless the PR is explicitly tagged `factory:bootstrap-pr`.
- The orchestrator is stateless across ticks. Work-item authority lives in the source of truth; operational state lives in local SQLite.
- New top-level directories imported by two or more apps must become pnpm workspace packages before cross-app imports land.
- Do not scope-creep. If related work belongs outside the current task, file or suggest a follow-up instead of doing it now.

## Stack

Use the existing stack: Node, pnpm, TypeScript, React, Vite, shadcn/ui, Drizzle, SQLite, Biome, Vitest, Playwright, and Zod. Do not add heavyweight dependencies without an ADR.

## Repository Lookup

`~/.factory/symbol-index.db` is a regenerable cache of exported symbols and imports. Use it for exact symbol discovery before broad text search when it fits the task.

- Build or refresh: `pnpm symbol-index` or `pnpm symbol refresh`
- Find a symbol: `pnpm symbol find <identifier>`
- Find static importers: `pnpm symbol callers <identifier>`
- Inspect a file: `pnpm symbol exports <file>` or `pnpm symbol imports <file>`

The index is not authority. Read the real files before reporting findings.

## Task Flow

1. Read the task or issue carefully and identify the acceptance criteria.
2. Read `CONTEXT.md` for relevant implementation decisions.
3. Read `FACTORY_RULES.md` for relevant rules.
4. Read app READMEs before touching app code.
5. If the task contradicts governance, stop and cite the rule.
6. If an architectural decision is missing for new `core/` behavior, write an ADR before opening the PR.
7. If the task remains ambiguous after reading the sources above, ask for human input. Do not guess on architecture.
8. Implement with focused tests and run the relevant checks before opening a PR.

## PRs And Issue Updates

- PR bodies must include `Closes #N` when the work is for issue `N`.
- PR bodies and issue transition comments must not include implementation reasoning that QA or Review holdouts should not see.
- After opening a PR, update completed acceptance criteria in the issue body and post a concise transition comment with the PR number and completed criteria.

## Decision Summaries

Decision summaries have two streams:

- Canonical: `decisionSummaries: Array<{kind, summary, evidence?}>` in the skill schema, emitted as `agent.decision-summary` after validation.
- Live: `[decision] KIND: <one sentence>` markers, forwarded best-effort by hooks.

`KIND` must be in `DecisionKindSchema` from `core/agent-runtime/decision-types.ts`; see ADR 0018. Summaries must be one sentence and must not contain raw chain-of-thought, secrets, API keys, file dumps, or PII.

Tool-call audit is automatic through `agent.tool-call`; do not write it manually.

## Never

- Do not run autonomously without explicit project config.
- Do not merge your own PRs in supervised mode.
- Do not bypass the tool allowlist for your role.
- Do not pretend to know things. If uncertain, say so and surface the question.

## When In Doubt

`CONTEXT.md` first. `MISSION.md` second. `FACTORY_RULES.md` third. Ask the human fourth. Guess never.
